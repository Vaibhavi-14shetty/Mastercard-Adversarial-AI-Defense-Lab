# 📖 Data Dictionary — Synthetic Payment World

Generated by Member 1 (`simulator/generators/`). All files live in `simulator/data/`.

**Reproducibility:** All generators are seeded (`random.seed(42)`, `np.random.seed(42)`,
`Faker.seed(42)`). Re-running any generator script produces identical output.

**Generation order (dependencies):**
```
entity_generator.py       → customers, accounts, cards, devices, merchants, beneficiaries
behavior_profile.py       → behavior_profiles (needs customers, devices, merchants)
transaction_generator.py  → transactions_historical (needs everything above)
```

## customers.csv

| Column | Type | Description |
|---|---|---|
| `customer_id` | string | Unique ID, format `C0001` |
| `name` | string | Synthetic Indian name (Faker `en_IN`) |
| `age` | int | 18–70 |
| `home_location` | string | One of 8 fixed cities (see Cities list below) |
| `signup_date` | date | When the customer joined |
| `risk_segment` | string | `low` / `medium` / `high` — background risk tier (not the same as `spending_band` in behavior_profiles) |

## accounts.csv

| Column | Type | Description |
|---|---|---|
| `account_id` | string | Format `A0001`, maps 1:1 to `customer_id` (e.g. `A0001` ↔ `C0001`) |
| `customer_id` | string | FK → customers.csv |
| `account_type` | string | `savings` / `current` |
| `opened_date` | date | Same as customer's `signup_date` |
| `balance` | float | ₹2,000–₹500,000 |

## cards.csv

| Column | Type | Description |
|---|---|---|
| `card_id` | string | Format `CARD0001` (some customers have a 2nd card, e.g. `CARD00012`) |
| `account_id` | string | FK → accounts.csv |
| `customer_id` | string | FK → customers.csv |
| `card_type` | string | `debit` / `credit` |
| `card_network` | string | `Mastercard` / `Visa` / `RuPay` |
| `issued_date` | date | |

**Note:** each customer has 1–2 cards. When joining, use the first card per customer
unless you specifically need multi-card behavior.

## devices.csv

| Column | Type | Description |
|---|---|---|

| `customer_id` | string | FK → customers.csv |

## behavior_profiles.csv

Per-customer "normal" baseline. **This is the key file for Blue Team's behavioral
detection and Red Team's attack design** — fraud is meaningful only relative to this.

| Column | Type | Description |
|---|---|---|
| `customer_id` | string | FK → customers.csv |
| `spending_band` | string | `low` / `medium` / `high` — derived from risk_segment with noise, drives amount distribution |
| `typical_amount` | float | This customer's "usual" transaction amount (₹) |
| `amount_std` | float | Natural variation around typical_amount (~35% of typical) |
| `preferred_merchant_ids` | **JSON string** | List of 2–8 merchant_ids this customer usually shops at. ⚠️ Parse with `json.loads()` — it's a string in the CSV, not a real list. |
| `preferred_categories` | **JSON string** | List of 2–4 merchant categories this customer sticks to. Also needs `json.loads()`. |
| `typical_device_ids` | **JSON string** | This customer's own device_ids from devices.csv. Also needs `json.loads()`. |
| `typical_location` | string | Same as customer's `home_location` |
| `hour_profile` | string | `morning_person` / `lunch_shopper` / `evening_shopper` / `night_owl` |
| `typical_hour_start` / `typical_hour_end` | int | 24hr clock bounds of their usual transaction window |
| `txns_per_week` | float | Expected transaction frequency |

**Example of parsing the JSON columns in Python:**
```python
import json
import pandas as pd

df = pd.read_csv("simulator/data/behavior_profiles.csv")
df["preferred_merchant_ids"] = df["preferred_merchant_ids"].apply(json.loads)
df["typical_device_ids"] = df["typical_device_ids"].apply(json.loads)
```

## transactions_historical.csv

The bulk synthetic dataset — **16,739 rows**, 90-day window, all legitimate
(`is_fraud=False`). Matches the team's frozen `Transaction` schema exactly
(see `simulator/schemas/transaction_schema.py`).

| Column | Type | Description |
|---|---|---|
| `transaction_id` | string | Unique, format `TX` + 10 hex chars |
| `customer_id` | string | FK → customers.csv |
| `account_id` | string | FK → accounts.csv |
| `card_id` | string | FK → cards.csv |
| `device_id` | string | FK → devices.csv (always one of the customer's own — this dataset has no fraud yet) |
| `merchant_id` | string | FK → merchants.csv (85% from customer's preferred list, 15% novel) |
| `beneficiary_id` | string or null | FK → beneficiaries.csv, present in ~15% of rows (P2P-style only) |
| `amount` | float | ₹, sampled from `Normal(typical_amount, amount_std)`, floored at ₹50 |
| `currency` | string | Always `INR` |
| `location` | string | 95% customer's home city, 5% travel |
| `timestamp` | ISO datetime | Mostly within customer's `hour_profile` window |
| `payment_method` | string | `card` / `upi` / `netbanking` / `wallet` |
| `is_fraud` | bool | **Always `False`** in this file — this generator only produces legitimate transactions |
| `attack_id` | null | **Always `null`** in this file — populated only by Red Team's attack injection |

## For Member 2 (Blue Team) — quick start

```python
import pandas as pd
import json

txns = pd.read_csv("simulator/data/transactions_historical.csv", parse_dates=["timestamp"])
profiles = pd.read_csv("simulator/data/behavior_profiles.csv")
profiles["preferred_merchant_ids"] = profiles["preferred_merchant_ids"].apply(json.loads)
profiles["typical_device_ids"] = profiles["typical_device_ids"].apply(json.loads)

# Join a transaction against its customer's baseline
merged = txns.merge(profiles, on="customer_id")
merged["amount_deviation"] = (merged["amount"] - merged["typical_amount"]) / merged["amount_std"]
```

## For Member 3 (Red Team) — quick start

Use `behavior_profiles.csv` to find what's "normal" per customer, then design attacks
that violate it. E.g., to build a `behavioral_evasion` attack (near-normal amount, but
new device):

```python
import pandas as pd, json, random

profiles = pd.read_csv("simulator/data/behavior_profiles.csv")
devices = pd.read_csv("simulator/data/devices.csv")

target = profiles.sample(1).iloc[0]
attack_amount = target["typical_amount"] * random.uniform(0.9, 1.1)  # near-normal
new_device_id = f"D{random.randint(90000,99999)}"  # NOT in their typical_device_ids — untrusted
```
